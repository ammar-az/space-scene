# Space

A desktop space-scene editor at [space.ammarz.com](https://space.ammarz.com), built with React, TypeScript, Three.js, Vite, and Cloudflare Workers. Its typography, blue glass surfaces, translucent header identity, and starter palettes follow [the portfolio](https://ammarz.com).

The app opens a starter system with a larger sun and portfolio-style side framing. The sun is cropped at the left edge; custom orbits can naturally extend outside the frame. Select a planet in the scene or object list to edit it. The broader direction is captured in [space-inspiration.md](space-inspiration.md).

## Development

Use Node.js **26.13.0 LTS**, pinned in `.node-version` for local development and Cloudflare Workers Builds.

```bash
npm ci
npm run dev
```

```bash
npm run check
```

The full check runs TypeScript, ESLint, regression/model tests, the production build, and a Cloudflare deployment dry run. `npm test`, `npm run build`, and `npm run preview` are also available. Pushing to `main` triggers the existing Cloudflare build/deployment integration.

`.work/` is intentionally ignored by Git. Keep progress in `.work/todo.md`, rendering decisions in `.work/notes/`, temporary presets/assets in `.work/assets/`, and verification images/results in `.work/verification/`. The local browser tooling and comparison copies of the old renderer also live there.

The minimal Worker returns 404 for requests not handled by Cloudflare's static asset layer. There is no application API. Regenerate runtime types with `npm run cf-typegen` after changing Worker bindings or compatibility settings.

## Current editor

- **Physical diameters** replace rendered radius fields. Planet `diameter` and `ranges.diameter` use **×1,000 km**; `sun.diameter` uses **×10,000 km**. Values round to hundredths (10 km planet precision, 100 km star precision). Logarithmic diameter sliders have linked scaled-unit and kilometre inputs; manual values beyond the initial slider span extend it. Numeric inputs commit on blur/Enter.
- **Scene presets → Body display sizes** controls geometric planet-size compression, an overall planet display multiplier, and an independent star multiplier (also in Sun settings). Compression 0% preserves physical planet ratios; 100% makes all planets match the largest planet. Hidden planets remain in that reference. The star is excluded. Physical diameters are never rewritten by display controls. Each diameter field shows **Rendered as** in the same physical units; hover/focus it for the compression and display-multiplier breakdown.
- Add, select, duplicate, hide, and delete planets. Click the Sun to open its settings and display its selection highlight.
- Rocky, gas, and icy families retain separate colors and surface settings when switching between them. Rocky planets have an **Atmosphere** tab for optional sunlit haze and a separate cloud layer. Configure haze color/density/height and cloud color/coverage/opacity/scale/altitude/drift/evolution; reroll cloud patterns independently. Gas/icy families keep their existing atmospheric surfaces.
- All color pickers keep intermediate previews local and commit on the native change event when selection finishes, avoiding repeated terrain/solar rebuilds during dragging.
- Enable **Earth-like surface** within Rocky for seeded continents, mostly blue ocean, green vegetation, yellow deserts and polar ice. Configure ocean/land/desert colors, land coverage and continent scale. First activation adds moderate clouds and blue haze; toggling it or switching families preserves later edits. Surface rerolls change continents while retaining these surface settings and independent cloud patterns.
- Adjust size, cratering, storm activity, icy band variation, moon count, bounded ring amount/width/opacity/inner edge, and actual spin-axis tilt.
- Set independent orbit X/Z radii, ellipse rotation, center X/Y/Z, inclination, plane orientation, signed speed and phase using sliders or numeric inputs. Fixed-center mode keeps shape and position independent; Sun-focus mode anchors either major axis to the Sun. Legacy orbit JSON keeps its original path until edited, and upgrades without a jump.
- Configure minimum/maximum ranges for the next reroll, with independent surface, moon, and ring seeds. Ring amount rolls continuously between 0 and 1; Ring chance controls whether a system is generated at all. Moon recipes define possible colors and ranges for orbit radius, speed, size and inclination; independent property streams keep recoloring from shuffling orbits. Distances/sizes are in parent radii; speeds are degrees per second. Short moon orbits expand to clear the planet and its rings.
- Lock a planet's appearance to exclude it from individual and scene rerolls. Locks protect randomization; deliberate manual edits still work.
- **Scene presets → Scene layout** provides **Orbit scale** and **Orbit spacing** (50–500%, default 100%). Scale expands each whole path about the Sun; spacing stretches gaps outward while retaining the innermost base orbit. The two factors compose without changing configured orbit axes/centers, body sizes, moon/ring systems, phases or periods. Reset layout returns both to 100%. Hidden planets retain their place in the spacing reference. Layout settings save separately in scene JSON.
- **Fit scene**, available in Scene layout and Camera, frames complete visible orbital paths and their satellites/rings/atmospheres while preserving the current angle. Zoom can go down to 0.01. Camera clipping adapts to the expanded scene.
- Use bird's-eye, centered side, and offset-sun side views as snap positions. Left drag pans in the current screen plane; right drag rotates around the current look-at point; scroll zooms. **Camera** opens horizontal/vertical angle sliders with precise number inputs and a zoom slider. Full 360° horizontal rotation and −90° to +90° vertical angles include below-plane and exact pole views. Named views and Reset view restore angle, target and zoom. The camera panel stays accessible while open in full screen.
- Pause the shared clock or reset orbital positions independently of starfield, spin, and solar activity.
- Use the visible **Orbits** toggle to show/hide orbit lines. **Full screen** (or `F`) expands the scene and reveals controls at the edges. Selecting an object keeps its inspector open. Escape returns to the editor. Revealed panels fill the full viewport height while their content stays below the header. A windowed focus mode is used if native fullscreen is unavailable.
- Edit star density, cluster frequency, large-star frequency, size, brightness, twinkling, and seed. Deep-sky photographs have independent visibility, density, size, brightness, and rerolling. The 1× defaults preserve the portfolio sky. Edit sun size, colors, seed, visibility, and independent solar activity.
- Export/import planet and whole-scene JSON presets. Import validates the entire file before applying it; imported planets receive fresh object IDs.
- **About** opens Ammar’s personal page, titled **My Space**, with one central reading column and room for his own astrophotography on either side. It retains the same starfield canvas. Photo metadata belongs in `src/react-app/data/about.ts`; no stock substitutes or invented personal photographs are included.

The **Portfolio system is the default scene**, generated immediately from its bundled JSON recipe. **Scene presets** offers [Portfolio system](public/presets/portfolio.json) and [Our solar system](public/presets/solar-system.json); **Generate scene** samples their declared ranges. Portfolio identities, colors and orbit layout stay recognizable while sizes, surfaces, moon counts and rings vary within the allowed bounds. Rocky worlds have no rings, gas giants have a 50% ring chance, and icy worlds have a 25% chance. Word Wasp starts earlier at the equivalent of the original 18° layout phase. Project X keeps its starting location on a closed, Sun-centered orbit with clearance throughout the period.

The solar recipe keeps eight named planets and Earth-like oceans/continents with white clouds and a blue atmospheric rim, plus dense cream-colored cloud cover on rocky Venus, with a separately scaled Sun, ordered neighboring orbits that clear the default rendered bodies/layers, compact representative moon systems, cream/tan/brown Jupiter, icy-style Saturn, and a narrow Uranus ring. Saturn uses the icy **visual** family by design. Composed axis orientation makes Uranus’s ring readable in the side view without changing its axial tilt. Faint Jupiter/Neptune rings remain omitted. Orbital periods, eccentricities, inclinations and axial tilts use the [NASA metric fact sheet](https://nssdc.gsfc.nasa.gov/planetary/factsheet/); physical diameters are rounded to hundredths in their scaled units, while displayed sizes and orbit distances are illustrative, and phases are composed rather than current ephemerides. Color/ring references: [Cassini’s Jupiter portrait](https://science.nasa.gov/photojournal/cassini-jupiter-portrait/) and [Uranus rings](https://www.jpl.nasa.gov/images/pia01977-uranus-rings/).

Generation replaces the current scene; export edits first. Importing exported JSON restores the exact sampled values and timeline rather than generating again. Recipe files live under `scene/presets/` and have identical public JSON download copies; tests enforce parity. The default is bundled so the generic three-planet starter never flashes before it.

The current editor state is in memory. Export JSON to keep a preset before refreshing or closing the page. Mobile work is intentionally deferred until the desktop experience is complete.

## Scene model and presets

`src/react-app/scene/model/schema.ts` defines strict, versioned JSON documents with a `kind` of `space-scene` or `space-planet`, `schemaVersion`, and `generatorVersion`. Schema **2** / generator **2** replace the old radius-based template; schema 1 files are intentionally unsupported. Unsupported versions, invalid values/ranges, duplicate scene IDs, and oversized files are rejected.

A planet records its explicit appearance, family settings, randomization ranges, seeds, lock, orbit, and spin separately. Ranges describe the next roll; changing them does not modify the current value. A scene contains complete object configurations, background, sun, camera, motion settings, and a snapshot of shared/solar time, with no external preset dependencies or GPU resources.

Optional `orbit.ellipse` stores explicit X/Z radii, in-plane rotation and anchor mode; it takes precedence over legacy scalar radius/eccentricity. Optional `rings` stores continuous amount, width, opacity and inner edge, overriding legacy `ringCount`; even legacy stacked belts now render as at most one full system. Optional `moons` stores palette and orbit/size ranges; individual moon profiles remain deterministic from the moon seed. Planet seeds accept bounded strings as well as numbers to preserve the portfolio artwork exactly; sun/starfield seeds remain numeric. Family `intense` is optional and preserves the portfolio’s original rocky crater recipe. Optional family `palette` constrains reroll colors; `bandShadow` gives giant belts and storms a coherent dark color (used for Jupiter’s warm bands). Optional `ranges.ringProbability` controls ring presence before the continuous amount is sampled. These constraints survive exports and rerolls. Optional `atmosphere` and `clouds` hold independent layer settings; `seeds.clouds` controls weather appearance independently of terrain, moon and ring streams. Omitted layers are disabled. Missing cloud seeds have a stable default that does not depend on other randomized parts or object identity. Optional `earthlike` settings select an ocean/continent surface within the rocky family; absence retains the original rocky appearance. Heights/altitudes use planet radii and cloud drift adds degrees per second to the current surface spin. Optional `clouds.evolution` controls bounded looping deformation independently of rotation (default 0.6; 0 holds its shape); all motion uses the shared clock. The two built-in presets use the new diameter/sizing schema; no migration path is provided for the discarded schema 1 format.

`model/sizes.ts` is the size authority. Required scene `sizing` stores `planetCompression` (0–1), `planetScale` and `starScale`. If `D` is a planet's physical diameter and `M` is the largest physical planet diameter, its compressed diameter is `M * (D / M) ** (1 - planetCompression)`. Multiply by `planetScale` for the Rendered as value. Star diameter only uses `starScale`. Both convert to scene radii at 0.16 world units per 1,000 km of diameter, with the star's 10× unit conversion applied explicitly. The renderer, satellite/layer geometry, shadows, picking/highlights, clipping and Fit scene all use these derived radii. The solar recipe uses rounded equatorial diameters from the [NASA planetary fact sheet](https://nssdc.gsfc.nasa.gov/planetary/factsheet/) and Sun diameter from twice the mean radius in the [NASA Sun fact sheet](https://nssdc.gsfc.nasa.gov/planetary/factsheet/sunfact.html). Solar defaults: 50% compression, planetScale 1, starScale 0.63. The portfolio uses fictional diameters converted from its previous composition, 0% compression and the same display multipliers.

`model/scene.ts` supplies pure creation and reroll operations. Each randomized part has its own stream; rerolling moons preserves the surface and rings. `model/geometry.ts` defines focus-centered ellipses and camera framing in common world units. Camera presets and manual camera edits do not rewrite object positions, orbital planes, or spin axes. Optional `layout` stores `orbitScale` and `orbitSpacing` as factors (1 means 100%); missing layout retains the original scene. The renderer applies a Sun-relative per-planet path transform to both mesh positions and orbit lines, leaving base orbit JSON intact. Optional `view.camera` stores azimuth/elevation, an explicit world-space target and unzoomed projection height; absent fields retain exact earlier framing. Entering free rotation captures the current composition without a jump, and subsequent zoom/resize retains the custom target. The last snap preset remains available for reset. `model/camera.ts` supplies pure rotation, screen-relative pan and snap operations. The renderer extends its clipping range for the free camera, while pointer capture separates pan/rotation from selection and cancels interrupted gestures. New scenes use the `portfolio` framing profile; existing JSON without a profile retains the earlier `standard` camera behavior. The side framing matches the portfolio’s 112% sun height and visible limb position while preserving a spherical 3D sun.

## Rendering

`scene/rendering/SceneRenderer.ts` owns one Three.js world, orthographic camera, sphere/ring geometry, ray picking, resource lifecycle, and animation. `rendering/materials.ts` adapts the portfolio's procedural maps and solar/storm/shadow shader functions to actual 3D meshes. Giant maps use equal-area coordinates; rocky maps use latitude coordinates. Material alpha is terrain height, not transparency. The legacy procedural shader color convention is retained explicitly rather than treating these maps as ordinary transparent image textures. Wrapped longitude derivatives prevent mipmap seams; planet maps clamp at the poles. Rings reuse the portfolio’s seeded radial opacity profile in a filtered, mipmapped texture instead of analytic fine stripes. Visible-sun lighting uses a softer terminator and 40% planet / 28% moon fill, with eclipses affecting direct light.

`rendering/atmospheres.ts` builds optional spherical cloud/haze shells only for rocky planets. The cloud field uses continuous 3D noise, avoiding longitude texture seams, and shares solar/eclipsing lighting with the surface. Clouds drift independently, follow live spin edits, and gently reshape through a bounded looping 3D flow offset. Evolution continues even with zero spin/drift and freezes with the scene clock. The haze is an artistic sunlit rim rather than a physical atmospheric-scattering simulation; it stays outside the cloud shell. Materials are disposed with their planet while the shared sphere geometry remains owned by the scene. `utils/earthMaps.ts` generates seam-continuous spherical continents and climate fields, with area-calibrated land coverage, ocean depth/coasts, green/desert regions and polar ice. These are generated Earth-like worlds rather than geographic maps of Earth. Cloud-cast surface shadows and richer surface rendering remain future work. Visual reference for Venus's cloud-covered appearance: [NASA Venus facts](https://science.nasa.gov/venus/venus-facts/).

`rendering/clock.ts` supplies shared pause, speed, visibility suspension, reduced-motion behavior, and snapshot restoration. Orbital reset uses its own epoch; solar activity has an independently pausable time. The starfield remains mounted above page-specific content and samples the same clock. Its deep-sky cutouts use the portfolio’s original selection, placement, screen blending, rotation, size, and opacity at default settings. Stars and deep-sky objects use independent seeds; omitted optional background fields use portfolio defaults. Cluster and large-star frequencies multiply the original per-site probabilities (0 disables that feature). Overall star density controls site density, so richer clusters add their member stars.

The old renderer projected DOM rectangles directly and allocated artificial depth bands to each planetary system. It was replaced because a common 3D world better supports the requested camera views, independent axes, ring planes, occlusion, and picking. Reference copies are in ignored `.work/reference/`; reusable generators remain under `scene/utils/` and palette data under `scene/data/`.

Further crater/storm shaping, ring appearance controls, manual object placement, and camera refinements can build on the current model. Generator changes must preserve existing version behavior or provide explicit migration/compatibility handling for saved presets.

## Background assets

`public/space/deep-sky/` contains 100 small transparent WebP thumbnails, their catalogue, and the original [credits](public/space/deep-sky/CREDITS.md). These render behind the procedural stars using the portfolio’s cutout treatment and are configurable in the Starfield inspector. Full-size photographs remain publisher links.

The same files are public at `https://ammarz.com/space/deep-sky/`, but the catalogue and sample thumbnail checked on November 2, 2026 lacked CORS permission for `https://space.ammarz.com`. Local copies avoid cross-origin fetch/canvas restrictions. The header logo and favicon are copied from the portfolio as local assets too.

## Verification

Node tests cover the original seeded-generator artwork, strict JSON validation and round trips, lock behavior, independent ranged rerolls, world-space orbit/view behavior, timeline snapshots, orbital resets, and clock suspension. Browser checks exercise the real WebGL renderer, selection, editing, import/export, view switching, and persistent starfield; screenshots and results belong in `.work/verification/`.

Current browser verification uses desktop Chromium with software WebGL. Hardware/browser diversity and mobile testing are separate follow-up work.

This physical-size pass was verified with TypeScript and a production build only, following the requested minimal-testing workflow. Existing model assertions were updated for schema 2 but were not run; historical `.work/` browser fixtures and authoring scripts target schema 1. Manual steps are in `.work/notes/physical-sizes-manual.md`.

Display multipliers use linear whole-percent sliders: planets100–500%, star10–100%, with a63% star default. Physical diameter sliders remain logarithmic.
